# Завдання 1. Видача решти: жадібний vs динамічне програмування

## Умова

Набір монет: `[50, 25, 10, 5, 2, 1]`. Реалізувати дві функції видачі решти й порівняти їх ефективність.

## Запуск

```bash
uv run task_01/main.py
```

## Реалізація

- `find_coins_greedy(amount)` — жадібний алгоритм: на кожному кроці беремо максимально доступний номінал.
- `find_min_coins(amount)` — динамічне програмування: будуємо таблицю `min_coins[0..amount]` та `coin_used[0..amount]`, потім відновлюємо набір монет.

Приклад для `amount = 113`:

```
greedy: {50: 2, 10: 1, 2: 1, 1: 1}
dp    : {1: 1, 2: 1, 10: 1, 50: 2}
```

## Аналіз складності

| Алгоритм | Час | Пам'ять |
| --- | --- | --- |
| `find_coins_greedy` | **O(k log k)** за рахунок сортування або **O(k)** при наперед відсортованому списку, де `k` — кількість номіналів | O(k) |
| `find_min_coins` | **O(n · k)** | **O(n)** |

`n` — сума решти, `k` — кількість номіналів. Жадібний не залежить від `n`, ДП — лінійно по `n` за пам'яттю та `n · k` за часом.

## Результати вимірювань

Заміри виконано через `timeit` (середнє за 5 запусків, для 1 000 000 — 1 запуск):

| Сума | greedy, с | dp, с | dp / greedy |
| ---:| ---:| ---:| ---:|
| 100 | 0.000001 | 0.000018 | ~24x |
| 1 000 | <0.000001 | 0.000205 | ~615x |
| 10 000 | <0.000001 | 0.002319 | ~7 500x |
| 100 000 | <0.000001 | 0.026491 | ~65 000x |
| 1 000 000 | 0.000002 | 0.280602 | ~120 000x |

Жадібний алгоритм фактично працює за константний час відносно `n` (тільки кількість номіналів впливає). Час ДП зростає лінійно: подесятикратне збільшення суми дає приблизно десятикратне зростання часу — як і прогнозує O(n · k).

## Висновки

1. **Швидкодія.** На великих сумах жадібний алгоритм у тисячі–сотні тисяч разів швидший. Його час не залежить від суми, тоді як ДП лінійно сповільнюється і споживає O(n) пам'яті.
2. **Коректність.** Для набору `[50, 25, 10, 5, 2, 1]` жадібний алгоритм дає оптимальний результат: цей набір є **канонічним** (кожен наступний номінал — кратний або «зручний» відносно решти), тому жадібний вибір збігається з мінімальним.
3. **Коли жадібний помиляється.** Жадібний не гарантує оптимум на довільних наборах. Класичний контрприклад: монети `[1, 3, 4]`, сума `6`. Жадібний дасть `4 + 1 + 1 = 3` монети, тоді як оптимально `3 + 3 = 2` монети. Саме в таких випадках ДП незамінне.
4. **Практична рекомендація.** Для касового апарату зі стандартним (канонічним) набором номіналів варто використовувати **жадібний алгоритм**: він простіший, не потребує пам'яті під таблицю та масштабується на будь-які суми. ДП доцільне лише за нестандартного набору номіналів, де жадібний втрачає оптимальність — і тоді його ціна (час та пам'ять O(n)) виправдана гарантією мінімуму.
